A kata can provide checks that run against your exercise. Use its Check action when available, then open Test results to see which cases passed or failed. A failing check is feedback about the current attempt, not a reason to reset all your work.

Read the failing case and its output. Ask the Sensei: “Help me understand this failure without writing the solution.” Include what you expected to happen. Save any work you want to keep before choosing a reset action.

An agent connection error and a failing test are different events. A connection failure does not prove that your code is wrong. If a check could not run, inspect the reported setup or command error first.

This interactive course has no kata check runner. Its authored recall question checks a short answer; it does not execute code or evaluate your machine.

See the [kata command](https://dojo.foo/docs/commands/kata) for the command-line workflow.
