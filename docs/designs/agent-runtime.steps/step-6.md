## What this step delivers

Pages are addressed by what is edited or studied. The authoring page moves to `/authoring/$draftId` and takes its workspace from the path for every authoring request and for the authoring watch socket. Learning moves to `/learn/$runId?lesson=<lessonId>`; `/session/$sessionId` and the old authoring and manual-trial forms redirect. Kyoshi's conversation comes from `POST /sessions/default` like Sensei's; the browser's own create and `POST /sessions` are deleted. A `?session=` in the URL is honoured only if it belongs to the page and is usable, and the page writes one only for a history pick. Records gain `firstMessage` and an `unavailable` mark. A history menu next to the persona dot on the kata lesson, interactive course and authoring pages lists the page's conversations on every agent; picking one on another agent switches the workspace's agent after confirmation (D31), and an ended Kyoshi conversation opens read-only with "Continue in a new conversation" (D32). The Trial tab opens `/learn/$runId`. A "Make this my current course" control is the only way the web UI changes `currentDojo` (D30). Tier A gains the four step-6 cases and the record is updated.

export interface SessionRecord {

  /** The opening of the first untagged learner or author message, written once by the pre-delivery hook (firstMessageOf) */

}
/** Whitespace collapsed; at most 80 characters including a trailing "…", cut at the last space before the limit when longer;

| record | row | Sensei pick | Kyoshi pick |
| --- | --- | --- | --- |
| live, selected agent | "live" | open it | open it |
| live, another agent | "live" | confirm switch, then open it | confirm switch, then open it |
| `unavailable` | "no longer available" | not openable | not openable |
| `replacedBy` | "replaced" | not openable | as ended |

| agent not in `GET /agents` | "<agent> isn't available" | not openable, no switch | not openable, no switch |

*   **Switch for a pick** uses `useWorkspaceAgent.request(agentId, pick)`: the same dialog and `select`, with the description "<today's persona sentence> The conversation continues if it still can; otherwise a new conversation starts on <agent>." (for a read-only pick: "It opens read-only."). *   **No bare error** (D33): a failed list read shows "Couldn't load the conversations." with "Try again" inside the menu. `chatFailure(error, { picked })` maps `409 agent_unavailable` on a picked conversation (another tab switched the agent) to `confirm-switch`, and `AgentChat` calls `onSwitchRequest(agent)`, which opens the confirmation for the picked agent and pick; on any other conversation it stays `default-open`.

## Decisions made in this plan

1.  **(Revised.) A new Kyoshi conversation still starts with the hidden `[dojo:begin-authoring]` turn, now sent by the UI server, without the page's `clientContext`.** The design removes the browser's create and says the begin turn is a separate send after a bodyless create; it names a begin turn only for Sensei (D29, item 3). Today every new Kyoshi conversation opens with Kyoshi's answer to that turn (fact 2), and nothing in the design asks to drop it. A server turn carries no `clientContext` (fact 2), so Kyoshi's opening reply no longer sees the open file; the author's first message carries it as today (`prepareSend`). Kyoshi has no begin contract to retry, so a failed start turn is logged, not replaced.
2.  **`/authoring/$draftId` is a flat route (`authoring_.$draftId.tsx`).** Nested under `authoring.tsx`, it would run the redirect route first; the trailing underscore is TanStack Router's way to share the path prefix without the parent. The old manual-trial redirect (`course_.$courseId.$.tsx`) uses the same form for the same reason.
3.  **The authoring helpers read the draft id from the path.** It keeps every call site of `authoringApi` and `request` unchanged (fact 1), including the bare-path calls that rely on the header; passing the id through 20 call sites changes more code for the same result.
4.  **The redirect for bare `/authoring` uses two existing reads, not `observeWorkspacePath`.** The design names `observeWorkspacePath`, which writes; `dojofoo ui --authoring` already registers the launch folder as a draft before it opens the page (fact 13), so a read finds it, and a GET that registers workspaces would change state on a preload.
5.  **`learning-sessions/:runId` resolves the course in the run's installation.** Without it the Trial tab's `/learn/$runId` fails as soon as a course id has two installations, which every second trial makes (fact 11). The dashboard's own "multiple installations" refusal (`routes.ts:164-167`) is unchanged; `viewLesson` no longer depends on it for the same course (decision 22).
6.  **(Revised.) Records gain `unavailable`, set only for an unreadable probe.** The menu's state comes from the record alone (D31). `usable()` writes `endedAt` both for a stranded or deleted conversation and for one that ended in Eve (fact 5); only the first is "no longer available", so the flag is set there alone and an ended Kyoshi conversation stays openable read-only (D32).
7.  **The D29 assertion that a new agent gets a new session id is tested in the UI server and the spec; tier A tests the per-agent half.** `packages/authoring` may not import the UI server, where the default rule lives. The tier-A cases cover what depends on the agent: a host on another agent runs nothing of this agent's conversation, a new session on this agent starts with no history from the old one, and the old one continues after switching back.
8.  **(Revised.) The away agent is `codex`, or `opencode` for Codex; it runs in its own driver process, home and wiring, and never gets a message.** Each agent's bootstrap lives in its own home and each child's environment is one agent's (fact 19), so the away host gets its own home with its bootstrap linked and its own wiring pointed at the case's loopback; a request it made would then be visible. Whether a host start spawns the agent's CLI is unverified; `expectNoNativeProcesses` over both homes shows nothing is left running.
9.  **`conformance` timeout 100 minutes.** Four cases per agent, each with three host starts and two turns (about 45 s, from step 4's 20 s per one-start case), add about 18 minutes for six agents to step 5's estimate of 51-59 minutes, which leaves too little of 80. Commit 7 times the four cases on one agent before the full run.
10. **(Revised.) "Make this my current course" is built here, and commit 8 adds it to the roadmap's Step 6 Builds.** D30 says `currentDojo` changes only through it, no step's Builds list names it, and traceability N17 asks for its file. It is one route and one button, sent as POST, as the design says.
11. **The dashboard's `sessions` field on `/api/control/courses` stays.** `LessonPage` still uses it to find a lesson from a requested session (`index.tsx:259,290`), and step 5's commit 9 rewrote it from records; nothing in this step needs it removed.
12. **`firstMessage` is written by the pre-delivery hook, as the design says; a refused first message can still name the conversation.** Writing it in `deliveries.after` on a 2xx would avoid that, but moves the write the design assigns to the pre-delivery hook; the composer keeps a refused message (D28), so the next send is almost always the same text. Accepted residual.
13. **The pick description says the conversation "continues if it still can"** (D31's wording), and "It opens read-only." for an ended Kyoshi pick, which would otherwise promise a continuation that cannot happen.
14. **(Review.) The fixture runtime and `default.ts` send `dojoTags.beginAuthoring` from protocol.** `packages/agent-api` may not import `packages/authoring` (fact 6); protocol already holds the same string.
15. **(Review.) Every navigate of the moved authoring page names `/authoring/$draftId`.** `/authoring` becomes the redirect route, so today's `navigate({ to: "/authoring" })` would leave the draft on every switch (fact 4).
16. **(Review.) A drop of `?session=` does not reload the chat.** Without the separate requested-id ref the prop change re-runs the open effect, clears the composer and loses the notice (fact 3); this matters for CUJ 4 and every stale link.
17. **(Review.) A pick's switch and its open are one page update.** Today `onSwitched` remounts the chat with no session (fact 4); if the pick were set afterwards, the remounted chat could open the new agent's default first, replace an ended newest record, start a turn and write `replacedBy` onto the very record being opened.
18. **(Review.) The "can't be continued" line is driven by the browser as well as the server's notice.** The fixture runtime reads no stream (fact 7), and on the real server a picked conversation can strand after the probe; a requested conversation that fails on open therefore drops `session` and opens the default plainly, not with `new`/`from`, so the newest usable conversation opens.
19. **(Review.) `notice` is set only for a requested record on the selected agent.** A stale link to another agent's live conversation (CUJ 4) can still be continued after a switch, so telling the learner it "can't be continued" would be wrong, and CUJ 4 says no error is shown.
20. **(Review.) Agents are "isn't available" when `GET /agents` does not list them; no per-agent `unavailable` field.** The first version added one for a missing CLI, but the only CLI the runtime refuses for is Cursor's (fact 8), and Cursor is not offered after step 5, so the field could never be set; an agent that `select` still refuses after the confirmation reaches the existing `agent_not_offered` outcome ("Choose another agent").
21. **(Review.) "Continue in a new conversation" sends `new: true` without `from`.** The design says it always creates a new conversation; with `from`, a replaced record would return its existing replacement (fact 5) and an ended one would gain `replacedBy` and change its row from "ended" to "replaced".
22. **(Review.) `viewLesson` keeps the page's `runId` for the same course.** The `courses` list it reads answers 409 once a course id has two installations (fact 9), which every second trial makes, and "Open next lesson", completion and `lesson.navigated` in a trial tab would then go to `/learn/` with an empty id.
23. **(Review.) `learning-sessions` reuses `courseInstallations` and the current-course route reuses `courseView`.** Both already compute what the first version added new code for (facts 11, 18).
24. **(Review.) The current-course route checks Origin.** It writes `.dojorc`, and the control routes already refuse a foreign Origin on writes (fact 18); hardening the other lesson routes stays in `local-api-hardening.md`.
25. **(Review.) Away-and-back asserts that the conversation continues on the same session and observes whether its history came back.** CUJ 3 and CUJ 7 require that switching back continues the old conversation, which the same-session reply shows. For the agent the switch is a host restart in between, and step 4 observes history after a restart (`senseiAnswerAfterRestart`, fact 19) rather than asserting it, because whether a native agent resends earlier turns after a cold restart is the adapter's recovery (design, "Lifecycle hook"). A `false` observation does not withdraw the agent; the step-4 resume case already asserts history where the design requires it.
26. **(Review.) The driver opens Kyoshi conversations bodyless, then sends.** From commit 2 that is how production opens every Kyoshi conversation, and the driver's create-with-message path would leave it untested on every agent.
27. **(Review.) The new-agent case asserts on what the loopback can see.** Loopback requests carry no Eve session id (fact 19), so the first version's "no request names `S0`" was true by construction; a marker sent in `S0`'s turn and absent from every request of `S1`'s process shows that the new session inherits nothing.
28. **(Review.) `agent-selector.spec.ts:45,132` stay.** Their `session=` comes from the `goto` URL and is honoured, so it remains; only `:29` (a new conversation after a switch) changes.
29. **(Review.) The specs outside the CI list get the edits their new addresses need, without joining the gate.** The design's list is cumulative and gated in CI (step 0); these specs are already outside it, and leaving their URLs on removed forms would only add to the known failures.
30. **(Review.) The command palette, not a "sidebar entry", is the dashboard's second course link.** The dashboard sidebar holds only Courses and Explore; the palette goes through `openCourse` (fact 10).
31. **(Review, mechanism replaced.) The away host is a separate driver process, not a second agent wired into one process.** The readiness review asked to link the away agent's bootstrap into the case home and merge its auth into the case child. A home links one `.ai-sdk-harness` directory and both agents' bootstraps live under that name, so one process cannot hold two; separate processes on one case root share the Eve World as the step-5 restart scenarios already do (fact 19), and each gets its own agent's home and wiring.
32. **(Implementation, commit 2.) `AuthoringChat`'s `notice` slot comes in commit 2, not commit 5.** The "can't be continued" status line ships in commit 2 and needs a place above the composer; commit 5 puts the read-only notice in the same slot.
33. **(Implementation, commit 2.) Each open mounts the conversation afresh (`AgentConversation` is keyed by the session and an open count).** When a requested conversation fails on open, the plain `POST /sessions/default` of the "History menu" can return that same conversation: the fixture runtime reads no stream (fact 7), and a real server can find it readable at its probe. Keyed by the session alone, the failed view would stay mounted with its recovery already spent; mounted again, its next failure is no longer a pick's and is replaced with `new` and `from`.
34. **(Implementation, commit 2.) The fixture's `failRead` also fails `POST /sessions/default`, and `agent-chat.spec.ts`'s history-read case fails a reload, not the first open.** The browser no longer reads `GET /sessions/{id}` to open a conversation, so `failRead` reached nothing; `eve-authoring.spec.ts`'s "reloading conversation history" case keeps its meaning through the default route. The failed-lookup case fails `POST …/sessions/default` instead of `GET …/sessions?*`, which the page no longer calls.
35. **(Implementation, commit 2.) `agent-selector.spec.ts`'s two launch-token cases accept the page's first token for the open and change the accepted token before the switch.** Kyoshi's page now opens its conversation through the token-checked default route, which spent the stale token those cases kept for `select`; changing the accepted token after the open stands for a relaunch between opening and switching, which keeps both cases about `select`.
36. **(Implementation, commit 2.) The out-of-CI `dashboard-authoring-runtime.spec.ts` and `eve-authoring-runtime.spec.ts` are edited in commit 4.** Both read the workspace id from the URL, which bare `/authoring` no longer carries once the page stops writing `?session=`; from commit 4 the id is in the path (`/authoring/<id>`), so their edit is made once there, with the session read from `GET /sessions`.
37. **(Implementation, commit 3.) `local-library.spec.ts` also gets `/learn/<run>` for its course-card `href` and its URL checks (`:139,246,256,291,294`).** Fact 20 names only its authoring URL (`:308`); its learning addresses are producers' output that changed in this commit, so they change with it (decision 29).

The old manual-trial redirect is `course_.$workspaceId.$courseId.lesson.$lessonId.tsx`, not the splat `course_.$courseId.$.tsx`.** TanStack Router's splat also matches an empty remainder, so `/course/$courseId/$` took `/course/<id>` itself and sent every installed course's page to the dashboard (`page-addressing.spec.ts` case 2 caught it). The old address has a fixed shape (fact 12), so the route names it exactly.
