## What this step delivers

Kata lessons run Sensei on the same Eve host and persona as interactive courses. The lesson page moves onto `AgentChat` and the page's default conversation (`POST /sessions/default` with `lesson`). Sensei gains the kata host-port methods (`context` for katas, `check`, `observe`, `show`, `navigate`) and tools (`dojo_lesson_verify`, `dojo_learner_observe`, `dojo_ui_show`, `dojo_lesson_complete`). The write guard lands: windows opened by the pre-delivery hook and before every server turn, closed by the pause and settle hooks, persisted in the guard store with quarantine, verified at UI-server start, at host start (recovery windows), at every host stop and at reconcile. Check reports become server-sent turns: sent when the session is idle, held otherwise, sent after the settle hook has been answered, and dropped on a save, a navigation, a leave cancel, an agent switch, a session end or a `context` read. The lesson socket is keyed by page, carries the presence signal, and drives the leave rule for kata lessons, interactive courses and (through the authoring watch socket) Kyoshi. An agent switch holds a bounded lock, times out to `interrupted`, and a single-UI-server lock protects `DOJOFOO_HOME`. Sensei sessions refuse `/compact` and `/clear`. The dashboard reads Sensei conversations from session records instead of `web.json` `threads`. The offered set is read from the conformance record. `test:lesson` is rewritten for Eve, tier A gains the step-5 cases, and the first Sensei results are recorded.

Evaluation trials keep the ACP path until step 7 (design, "Where each path runs").

### Harness file guard (`packages/agent/src/file-guard.ts`, export `./file-guard`)

```ts
export interface GuardWindow { id: string; owner: string; path: string; existed: boolean; sha256?: string; openedAt: string; meta: Record<string, string> }
export interface GuardVerdict { window: GuardWindow; action: "unchanged" | "restored" | "recreated" | "removed"; quarantined?: string }
export function createFileGuard(directory: string): {
  /** Rule 1: a byte copy of `path`, written before the window record; returns the owner's open window if it has one */
  open(owner: string, path: string, meta?: Record<string, string>): Promise<GuardWindow>;
  find(owner: string): Promise<GuardWindow | undefined>;
  list(): Promise<GuardWindow[]>;
  /** A UI-server write while windows are open on `path` (null: the file was removed) updates their copies; the caller holds withPathLock(path) */
  update(path: string, content: Uint8Array | string | null): Promise<void>;
  /** Rule 2: a delivery that opened the window was refused */
  discard(windowId: string): Promise<void>;
  /** Rule 3: restore a changed file from the copy, quarantine the other version, close the window; a closed window is a no-op */
  verify(windowId: string): Promise<GuardVerdict | undefined>;
};
/** Temp file and rename */
export function writeFileAtomic(path: string, content: Uint8Array | string): Promise<void>;
/** One in-process lock per resolved path, shared by writeSolution and verify */
export function withPathLock<T>(path: string, run: () => Promise<T>): Promise<T>;
```

Layout under `directory`. The UI server passes `$DOJOFOO_HOME/state/guard/<root key>`, where `<root key>` is the first 16 hex characters of the SHA-256 of the workspace's resolved folder, so every caller that holds only the folder (`writeSolution`) and every caller that holds a workspace id (resolved to the folder with `resolveWorkspaceId`) finds the same store (decision 25). `windows/<id>.copy` then `windows/<id>.json` (the record is the marker, written last with temp and rename, so a crash between the two leaves no window; `meta` holds `root`, `workspaceId`, `sessionId`, `courseId`, `lessonId` and `turnId` when known); `quarantine/<sha256(path)>` with `quarantine/<sha256(path)>.json` (`{ path, at }`), one per path, replaced at the next violation on that path; `notices.json` (UI-server notices raised outside a socket, below).

## Guard (UI server)

Two modules, so the lesson services can reach the guard without a cycle (decision 25): `packages/ui/src/server/agent-session/guard-store.ts` wraps the harness file guard for one workspace folder (`guardFor(root)`, `updateOpenWindows(root, path, content)`, `verifyAllWindows(stateDirectory)`) and imports nothing of the UI server; `packages/ui/src/server/agent-session/guard.ts` holds the policy and imports `guard-store.ts`, the lifecycle, the records and `clearCheckResult` from `lesson/service.ts`. `service.ts` imports only `guard-store.ts`.

*   **Owner and scope.** A window's owner is the Eve session id. Only Sensei records with a `courseId` whose course is a kata course and a `lessonId` get windows; Kyoshi and interactive courses get none (design, "Write guard": no-op).
*   **Rule 1, pre-delivery.** `deliveries.before` (session API proxy) and every server turn (begin, check report) call `openWindow(root, record)` before the lifecycle's `pre-delivery` transition, unless the owner already has a window. The handle returned to `deliveries.after` carries `{ before: LifecycleStatus, opened?: windowId }`; a non-2xx answer discards only a window that this delivery opened (rule 2). Whether Eve ever accepts a delivery without starting a turn is still unverified (step 4 fact list); the reconcile below closes such a window.
*   **Rule 2, close.** The host-port `turn.paused` and `turn.settled` handlers verify the owner's window before the lifecycle transition, with the host port's idempotency per `(turnId, event)` (step 4).
*   **Rule 3, verify.** A `GuardVerdict` with an action other than `unchanged` clears the lesson's check result (`clearCheckResult`, commit 3), drops a held report (`report-dropped`), and emits a `GuardViolation` to the page key's sockets. When no socket for the page key is open, the violation goes to `notices.json` and is sent, then removed, when a socket for that page key next opens (design: "A notice raised at host start is persisted and shown when the lesson next opens").
*   **UI-server writes.** `writeSolution` (commit 3) writes inside `withPathLock(path)`; from commit 5 it calls `updateOpenWindows(root, path, content)` inside that same lock, so a save during a working turn is kept (D21) and cannot interleave with a verify.
*   **Verification points** (design, "Startup and recovery order"): every window at UI-server start, before any host starts, as `for (const window of await guard.list()) await guard.verify(window.id)` in each store (commit 6); a recovery window for each record of the host's agent with status `working` before the host starts (commit 6); every window of a host's sessions before that host stops for any reason (switch, switch timeout, crash, idle stop, `stop`), with held reports dropped (commit 6) and leave timers cleared (commit 8); at reconcile for each record it settles (commit 6); when a session is replaced (commit 5).

## Presence and leaving (`packages/ui/src/server/agent-session/presence.ts`)

*   **One hub per process.** The hub lives at `Symbol.for("dojofoo.presence")` on `globalThis`, like the host-port registry (`host-port.ts:23-25`), so every Nitro chunk that loads the module shares it.
*   **Page keys.** A socket opening with `workspace`, `course` and `lesson` joins the kata page key `(workspace, course, lesson)`; with `workspace` and `course` only, the interactive key `(workspace, course)`. The hub keeps a peer set per key, so two tabs on one lesson count as one page.
*   **Leave triggers.** A socket opening for key K leaves every other key of the same workspace that has a session to cancel (design: "Any lesson or course socket that opens for a different page key in the workspace leaves the current page, across course types"). The last peer of K closing starts a 30-second timer; any socket for K opening clears it; when it fires, K is left. Evaluation-trial workspaces never count as left; manual trials follow the learner rule (their kind is `learner`).
*   **Who cancels.** Leaving K runs, for each of K's records on the selected agent that is `paused` or `working` with `beginPending`: `applyLifecycle(root, id, { type: "leave" })`, then `runtime.cancelTurn(workspaceId, sessionId, turnId?)`, a new AgentRuntime method that attaches to the record's host endpoint (only if that host is running) and sends Eve's cancel with the paused `turnId`, or without one for a working begin (commit 8).
*   **After a restart.** When a host becomes ready (after reconcile), the hub arms the 30-second timer for each `paused` record of the host's agent whose page key has no peer (design, "Startup and recovery order", item 5; commit 8).
*   **Kyoshi.** `authoringWatchers` gains `onLeft(listener)`: 30 seconds after a draft's last authoring socket closes without another opening, the listener runs. The AgentRuntime cancels the draft's `paused` Kyoshi records with their `turnId` through `cancelTurn`; D27 evicts their native sessions.
*   **Idle stop** (design, "Persona hosts"): a host is idle when its workspace has no lesson or course socket, no authoring watcher, no open proxied stream, and no record on the host's agent `working` or `paused`; the 15-minute bound counts from the moment it became idle. The proxied-request presence from step 4 (decision 6) is removed.

## Switch lock, switch timeout and `interrupted` (`agent-api.ts`)

`select` runs, holding the per-workspace switch lock: drop every held report of the workspace; cancel each record of the old agent (`turnId` when paused, none when working); wait up to `switchSettleMs` (10 s) for their settles; mark those still open `interrupted` (`switch-timeout` with the open turn's id, window verified); verify and close the host's remaining windows; close the host and reap its process record (`reapProcessGroups`); save the selection. Every waiter (`connect`, `start`, `openDefault`, `deliveries.before`, host auto-restart) waits at most `switchSettleMs + hostStopMs` (`hostStopMs` 10 s, new option) and then answers 409 `agent_switching`. From commit 9, `select` refuses Cursor for a learner workspace while `senseiRefusesCursor` holds (step 4 decision 19, extended to kata), until commit 12 replaces it with the offered set.

**Interrupted turns never run again** (decision 6). Sensei's model definition calls host-port `turn.check { turnId: ctx.turn?.id }` on every model call, outside any memo, before it builds the harness model. A host of any agent that recovers an `interrupted` session's run (Eve recovers it, fact 10) therefore gets 409 `turn_interrupted`; the model definition throws `new Error("This turn was interrupted by an agent switch.")` with no `statusCode`, so no native agent starts and Eve fails the turn with `REACTION_FAILED` (fact 14). The chat shows a failed turn whose code is `REACTION_FAILED` and whose message contains "interrupted by an agent switch" as stopped, without an alert; whether Eve passes the message through to `turn.settled.data.error` is unverified, and tier A records the observed error (`interruptedTurnError`) so the matcher can follow it.

## Single-UI-server lock (`packages/ui/src/server/server-lock.ts`)

`acquireServerLock({ stateHome, url, waitMs = 15_000, exit = process.exit })`: `openSync(<stateHome>/ui.lock, "wx")` and write `{ pid, startedAt: processStartTime(pid), url }`. A lock that names this process (`pid === process.pid`, as when the dev runner loads the module twice) counts as taken. When the file exists and its `pid` is not alive or its `startedAt` differs, replace it (temp file and rename). Otherwise poll every 250 ms for up to `waitMs` (a synchronous sleep with `Atomics.wait`, because nothing may run before the lock), then print "Dojofoo is already running at <url>." to stderr and call `exit(1)`. `releaseServerLock(stateHome)` removes the file only if it still names this process; it runs on Nitro `close` and on `process` `exit`.

It is taken in one place, `startUiServer(options)`, as its first step, with `stateHome = dirname(localStateDirectory(options))`, so `startup.test.ts`'s temporary state home gets its own lock (released in the test's `finally`). The Nitro plugin calls `startUiServer()` with the lock step outside its `try` (a refusal must stop the server; the backfill's errors stay swallowed). `url` is `DOJO_UI_BASE_URL`, else `http://<HOST or 127.0.0.1>:<PORT>`. In portless mode the CLI's forced route update `SIGTERM`s the old server (fact 21), whose `close` hook releases the lock, so the new one waits at most for that shutdown.

## Decisions made in this plan

1.  **The guard's file mechanics live in the harness (`@dojofoo/agent/file-guard`); the UI server owns its policy and state.** The design puts the guard in the UI server, and that is where windows open and close, where the store sits and where violations reach the learner. The scripted guard cases are tier-A cases in `packages/authoring`, which may not import `packages/ui` (fact 17); a generic copy, verify, quarantine and atomic-write module imports no persona (D11), as the host-port skeleton does.
2.  **`dojo_lesson_complete` is a static workflow tool that refuses for interactive courses; the other kata tools are dynamic and left out for them.** The design calls `complete` a workflow tool, and step 4's plan said kata tools would be dynamic; Eve does not allow a workflow body in a dynamic tool (fact 13). D17's "tools depend on the course type" holds for every tool but this one, which the interactive instructions never mention and which answers `unavailable` if called. Its I/O (the mode lookup and `navigate`) runs in `"use step"` functions, because the body replays.
3.  **The scripted harness is exported as `@dojofoo/agent/scripted-harness`.** The tier-A runner needs it, a relative cross-package import is forbidden, and `./host-port/fixture` already sets the pattern for test fixtures in the harness's exports. The object is moved unchanged; the runner supplies its instruction marker and `root_only` tool (decision 24).
4.  **Scripted guard cases run in `full` mode.** The scripted harness is not a registry agent, so a read-only allow-list has nothing to apply to; its file changes are its own `node:fs` calls, which is what the guard backstops (a native CLI that writes without asking).
5.  **Listed (Grok-only) and scripted cases count toward the agents they run on.** Today the record ignores them (fact 18), so `sensei.acp.model-probe`, which settles open risk 3 for Grok, and the guard cases would never decide whether Sensei passes. Scripted cases are agent-independent, so each per-agent process runs them once and each agent's entry carries their outcome.
6.  **(Revised.) An interrupted turn, or another agent's session, is refused by an un-memoised host-port `turn.check` on every model call.** Eve recovers every active run in the workspace's one World at host start, whatever agent started it (facts 9, 10), and the design's "a host never recovers another agent's session" and "never continued by Claude Code" (CUJ 3) need a mechanism. The first version put the refusal in the memoised `session` read, which a recovered turn would answer from its saved memo (fact 14); the check now runs outside any memo and keys on `interruptedTurnId` as well as the status, so a learner delivery that clears `interrupted` first cannot let the old turn continue (decision 33). The failure surfaces as `REACTION_FAILED`, not as a code of ours (fact 14).
7.  **A delivery to an `interrupted` session moves it to `working`.** The design's table lists pre-delivery from `idle` and `paused` only, which would leave a switched-back conversation unable to continue (CUJ 3 says it continues). Commit 12 updates the table.
8.  **`sensei.host.start-after-eve-version-change` emulates the version change.** Tier A has one Eve version, so it cannot build a session another version would strand. The case produces the state the design's reconciliation exists for (a turn settled in Eve whose settle hook never reached the UI server, which Eve does not rerun, `execution-model-and-durability.mdx:143,186`) and checks what reconcile relies on; the UI-server reconcile itself is tested in `agent-api.test.ts`. A real version change is left to the release check (tier B).
9.  **Open risk 4's mitigation is an `afterAnswer` callback in the host-port skeleton, not a timer.** The design requires the held report to go out only after the settle hook's call is answered; a `setTimeout` in the handler can fire before the response is written. Running the work after the body's last chunk is pulled ties it to the answer; the tier-A case records whether Eve would have waited anyway.
10. **The offered set switches to the record in the record commit.** The record has no Sensei result before this step's CI run (step 4's entries say `untested`), so switching earlier would offer no agent and break every commit after it. The switch and the record land together, and so do the test updates that assume today's list.
11. **From commit 12 Cursor is not offered for either persona.** The design's rule (D1, "Offered agents": from step 5, a row is offered when its latest record passes for both personas) has this consequence because Cursor has no record until its tier-B run; until commit 12, step 4's Cursor gate is extended from interactive to kata Sensei (and to `select` for learner workspaces) in commit 9, when kata Sensei moves to Eve.
12. **Kata observations take their sources from Eve's evidence store and stay in `web.json` `learnerObservations`.** `recordLearnerObservation` requires a cited excerpt (`learner-observations.ts:14`), and Eve sessions' excerpts are in `.dojo/learner-evidence.json` (step 4); the observations' own store is unchanged because nothing else reads them and step 7 decides `web.json`'s future.
13. **The shipped record is a JSON import in protocol.** The design puts the registry and the record in protocol (step 3 decision 6) and the browser's evaluation settings read `offeredAgents()` (fact 19), so the record must load without `node:fs`. Protocol's `tsconfig.json` moves to `module: "ESNext"` for the import attribute (fact 19). If `tsc` does not emit `dist/conformance.json` (commit 1's check), protocol's `build` script copies it after `tsc`.
14. **Commits 9 and 10 are pushed together.** The rewritten page cannot pass the ACP `test:lesson`, and the Eve `test:lesson` cannot pass before the page moves; each commit still type-checks and builds, which is the roadmap's rule for every commit.
15. **The composer hint while a question is open reads "Answer Sensei's question above, or type your answer".** The design lists the hint (traceability R6) without its text; a typed message answers the first open question (Eve docs `tools/human-in-the-loop.md:338,346`), which the hint says.

18. **(Revised.) Every settle of a record with `resumeFailedAt` replaces the session in the UI server and sends `session.replaced`; the begin's own failure is still answered inside `POST /sessions/default`.** D16 sends a held report "after any replacement has run", so the replacement must run where the report waits, at the settle; it runs under the page key's lock, so a browser asking at the same time gets the same replacement (D28).
