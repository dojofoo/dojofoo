## What this step delivers

Kata lessons run Sensei on the same Eve host and persona as interactive courses. The lesson page moves onto `AgentChat` and the page's default conversation (`POST /sessions/default` with `lesson`). Sensei gains the kata host-port methods (`context` for katas, `check`, `observe`, `show`, `navigate`) and tools (`dojo_lesson_verify`, `dojo_learner_observe`, `dojo_ui_show`, `dojo_lesson_complete`). The write guard lands: windows opened by the pre-delivery hook and before every server turn, closed by the pause and settle hooks, persisted in the guard store with quarantine, verified at UI-server start, at host start (recovery windows), at every host stop and at reconcile. Check reports become server-sent turns: sent when the session is idle, held otherwise, sent after the settle hook has been answered, and dropped on a save, a navigation, a leave cancel, an agent switch or a `context` read. The lesson socket is keyed by page, carries the presence signal, and drives the leave rule for kata lessons, interactive courses and (through the authoring watch socket) Kyoshi. An agent switch holds a bounded lock, times out to `interrupted`, and a single-UI-server lock protects `DOJOFOO_HOME`. Sensei sessions refuse `/compact` and `/clear`. The dashboard reads Sensei conversations from session records instead of `web.json` `threads`. The offered set is read from the conformance record. `test:lesson` is rewritten for Eve, tier A gains the step-5 cases, and the first Sensei results are recorded.

Evaluation trials keep the ACP path until step 7 (design, "Where each path runs").

### Harness file guard (`packages/agent/src/file-guard.ts`, export `./file-guard`)

```ts
export interface GuardWindow { id: string; owner: string; path: string; existed: boolean; sha256?: string; openedAt: string; meta: Record<string, string> }
export interface GuardVerdict { window: GuardWindow; action: "unchanged" | "restored" | "recreated" | "removed"; quarantined?: string }
export function createFileGuard(directory: string): {
  /** Rule 1: a byte copy of `path`, written before the window record; returns the owner's open window if it has one */
  open(owner: string, path: string, meta?: Record<string, string>): Promise<GuardWindow>;
  find(owner: string): Promise<GuardWindow | undefined>;
  list(): Promise<GuardWindow[]>;
  /** A UI-server write while windows are open on `path` (null: the file was removed) updates their copies */
  update(path: string, content: Uint8Array | string | null): Promise<void>;
  /** Rule 2: a delivery that opened the window was refused */
  discard(windowId: string): Promise<void>;
  /** Rule 3: restore a changed file from the copy, quarantine the other version, close the window; a closed window is a no-op */
  verify(windowId: string): Promise<GuardVerdict | undefined>;
};
/** Temp file and rename, under a per-path lock shared with the guard */
```

## Guard (UI server, `packages/ui/src/server/agent-session/guard.ts`)

*   **Owner and scope.** A window's owner is `<workspaceId>:<sessionId>`; `meta` holds `courseId`, `lessonId`, `turnId` when known. Only Sensei records with a `courseId` whose course is a kata course and a `lessonId` get windows; Kyoshi and interactive courses get none (design, "Write guard": no-op).
*   **Rule 1, pre-delivery.** `deliveries.before` (session API proxy) and every server turn (begin, check report) call `openWindow(path, record)` before the lifecycle's `pre-delivery` transition, unless the owner already has a window. The handle returned to `deliveries.after` carries `{ before: LifecycleStatus, opened?: windowId }`; a non-2xx answer discards only a window that this delivery opened (rule 2). Whether Eve ever accepts a delivery without starting a turn is still unverified (step 4 fact list); the reconcile below closes such a window.
*   **Rule 2, close.** The host-port `turn.paused` and `turn.settled` handlers verify the owner's window before the lifecycle transition, with the host port's idempotency per `(turnId, event)` (step 4).
*   **Rule 3, verify.** `GuardVerdict` with an action other than `unchanged` clears the lesson's check result (`clearCheckResult`, commit 3), drops a held report (`report-dropped`), and emits a `GuardViolation` to the page key's sockets. When no socket for the page key is open, the violation goes to `notices.json` and is sent, then removed, when a socket for that page key next opens (design: "A notice raised at host start is persisted and shown when the lesson next opens").
*   **UI-server writes.** `writeSolution` (commit 3) calls `guard.update(path, content)` for every open window on the path inside the same path lock, so a save during a working turn is kept (D21).
*   **Verification points** (design, "Startup and recovery order"): every window at UI-server start, before any host starts (commit 6); a recovery window for each record of the host's agent with status `working` before the host starts (commit 6); every window of a host's sessions before that host stops for any reason (switch, switch timeout, crash, idle stop, `stop`), with its leave timers cleared and held reports dropped (commit 6); at reconcile for each record it settles (commit 6); when a session is replaced (commit 5).

| --- | --- | --- |

| `turn.paused` | `working` → `paused` | guard verify; leave timer armed when no socket for the page key is open |
| `turn.settled` (`outcome`) | `working`, `paused` → `idle`; `interrupted` unchanged | guard verify; evidence; a begin settled `cancelled` with `beginPending.cancelledAt` keeps `beginPending` (D29's resend with a new key), otherwise clears it; a completed kata begin marks the lesson introduced; held report sent after the answer |
| `leave` | `paused`, or `working` with `beginPending` | held report dropped, then Eve cancel (with `turnId` when paused; without it for a working begin); `beginPending.cancelledAt` set for a begin |

## Check reports (`packages/ui/src/server/agent-session/check-reports.ts`)

*   `offerCheckReport(workspaceId, courseId, lessonId, observation)` runs after every learner Check (socket `lesson.check` and `POST …/checks`). It finds the page key's newest usable record on the selected agent (no `endedAt`, no `replacedBy`). With none, the card says "Sensei hasn't seen this; press Check again or ask" (`dropped`). With status `idle` and no `beginPending`, it sends now; otherwise it stores `heldReport` (replacing an older one) and the card says "Sensei will see this after it finishes" (`held`).
*   The report text is `[dojo:check] Ran lesson checks.` followed by a blank line and the JSON today's ACP context resource carries (`instruction` from `checkObservationInstruction`, `attempt`, `codeChanged`, `diff`, `report`; `service.ts:529-543`). The tag hides it in the chat and keeps it out of learner evidence.
*   `sendServerTurn(path, endpoint, record, { text, idempotencyKey })` is shared with the begin turn (moved out of `default.ts:79-100`): window (rule 1), `pre-delivery`, then `POST <host>/eve/v1/session/<id>` with `{ message, idempotencyKey, turnPolicy: "queue" }` for a report (`check:<sessionId>:<observationId>`) and `{ message, idempotencyKey }` for the begin, retrying `409 session_not_ready` for 20 s. It returns Eve's `deliveryId`. A refusal runs the delivery-rejected transition and drops the report.
*   A held report is sent from `turn.settled`'s `afterAnswer` (open risk 4), after any replacement has run (D16): when the record has `resumeFailedAt`, the Replacement rule runs first (`openDefault` with `new` and `from`, under the page key's lock), `session.replaced` goes to the page key's sockets, and the report is held on the new session until its begin settles.
*   Drops (D16): a learner save of the lesson's solution (`PUT …/files/solution`), `navigate`, a `leave`, an agent switch (all held reports of the workspace), a guard violation; "seen" on `delivery.consumed` of the sent report's delivery or a kata `context` read whose `latestCheck` is the report's observation.

## Presence and leaving (`packages/ui/src/server/agent-session/presence.ts`)

*   **Page keys.** A socket opening with `workspace`, `course` and `lesson` joins the kata page key `(workspace, course, lesson)`; with `workspace` and `course` only, the interactive key `(workspace, course)`. The hub keeps a peer set per key, so two tabs on one lesson count as one page.
*   **Leave triggers.** A socket opening for key K leaves every other key of the same workspace that has a peer-less timer or a session to cancel (design: "Any lesson or course socket that opens for a different page key in the workspace leaves the current page, across course types"). The last peer of K closing starts a 30-second timer; any socket for K opening clears it; when it fires, K is left. Leaving K runs the `leave` transition for K's records on the selected agent that are `paused`, or `working` with `beginPending`. Evaluation-trial workspaces never count as left; manual trials follow the learner rule (their kind is `learner`).
*   **Kyoshi.** `authoringWatchers` gains `onLeft(listener)`: 30 seconds after a draft's last authoring socket closes without another opening, the listener runs. The AgentRuntime cancels the draft's `paused` Kyoshi records with their `turnId`; D27 evicts their native sessions.
*   **Idle stop** (design, "Persona hosts"): a host is idle when its workspace has no lesson or course socket, no authoring watcher, no open proxied stream, and no record on the host's agent `working` or `paused`; the 15-minute bound counts from the moment it became idle. The proxied-request presence from step 4 (decision 6) is removed.

## Switch lock, switch timeout and `interrupted` (`agent-api.ts`)

`select` runs, holding the per-workspace switch lock: drop every held report of the workspace; cancel each record of the old agent (`turnId` when paused, none when working); wait up to `switchSettleMs` (10 s) for their settles; mark those still open `interrupted` (`switch-timeout`, window verified); verify and close the host's remaining windows; close the host and reap its process record (`reapProcessGroups`); save the selection. Every waiter (`connect`, `start`, `openDefault`, `deliveries.before`, host auto-restart) waits at most `switchSettleMs + hostStopMs` (`hostStopMs` 10 s, new option) and then answers 409 `agent_switching`. From commit 9, `select` refuses Cursor for a learner workspace while `senseiRefusesCursor` holds (step 4 decision 19, extended to kata), until commit 12 replaces it with the offered set.

A host of any agent that recovers an `interrupted` session's run (Eve recovers it, fact 10) fails that run at its first model call: the Sensei model's `session` read answers 409 `turn_interrupted`, the model definition throws an error with code `turn_interrupted` and no `statusCode`, so no native agent starts (decision 6). The chat shows that turn as stopped, without an alert.

## Single-UI-server lock (`packages/ui/src/server/server-lock.ts`)

`acquireServerLock({ stateHome, url, waitMs = 15_000 })`: `openSync(<stateHome>/ui.lock, "wx")` and write `{ pid, startedAt: processStartTime(pid), url }`. When the file exists and its `pid` is not alive or its `startedAt` differs, replace it (temp file and rename). Otherwise poll every 250 ms for up to 15 s (a synchronous sleep with `Atomics.wait`, because Nitro's plugin is synchronous and nothing must run before the lock), then print "Dojofoo is already running at <url>." to stderr and `process.exit(1)`. `releaseServerLock()` removes the file only if it still names this process; it runs on Nitro `close` and on `process` `exit`. `<stateHome>` is `dirname(localStateDirectory())`; `url` is `DOJO_UI_BASE_URL`, else `http://<HOST or 127.0.0.1>:<PORT>`.

## Decisions made in this plan

1.  **The guard's file mechanics live in the harness (`@dojofoo/agent/file-guard`); the UI server owns its policy and state.** The design puts the guard in the UI server, and that is where windows open and close, where the store sits and where violations reach the learner. The scripted guard cases are tier-A cases in `packages/authoring`, which may not import `packages/ui` (fact 15); a generic copy, verify, quarantine and atomic-write module imports no persona (D11), as the host-port skeleton does.
2.  **`dojo_lesson_complete` is a static workflow tool that refuses for interactive courses; the other kata tools are dynamic and left out for them.** The design calls `complete` a workflow tool, and step 4's plan said kata tools would be dynamic; Eve does not allow a workflow body in a dynamic tool (fact 13). D17's "tools depend on the course type" holds for every tool but this one, which the interactive instructions never mention and which answers `unavailable` if called.
3.  **The scripted harness is exported as `@dojofoo/agent/scripted-harness`.** The tier-A runner needs it, a relative cross-package import is forbidden, and `./host-port/fixture` already sets the pattern for test fixtures in the harness's exports. The object is moved unchanged.
4.  **Scripted guard cases run in `full` mode.** The scripted harness is not a registry agent, so a read-only allow-list has nothing to apply to; its file changes are its own `node:fs` calls, which is exactly what the guard backstops (a native CLI that writes without asking).
5.  **Listed (Grok-only) and scripted cases count toward the agents they run on.** Today the record ignores them (fact 16), so `sensei.acp.model-probe`, which settles open risk 3 for Grok, and the guard cases would never decide whether Sensei passes. Scripted cases are agent-independent, so each per-agent process runs them once and each agent's entry carries their outcome.
6.  **A recovered run of an `interrupted` session, or of another agent's session, fails at its first model call through host-port `session`.** Eve recovers every active run in the workspace's one World at host start, whatever agent started it (facts 9, 10), and the design's "a host never recovers another agent's session" and "never continued by Claude Code" (CUJ 3) need a mechanism. Refusing in the model definition stops the run before any native process starts and needs no Eve change; the error has no `statusCode`, so Eve does not retry.
7.  **A delivery to an `interrupted` session moves it to `working`.** The design's table lists pre-delivery from `idle` and `paused` only, which would leave a switched-back conversation unable to continue (CUJ 3 says it continues). Commit 12 updates the table.
8.  **`sensei.host.start-after-eve-version-change` emulates the version change.** Tier A has one Eve version, so it cannot build a session another version would strand. The case produces the state the design's reconciliation exists for (a turn settled in Eve whose settle hook never reached the UI server, which Eve does not rerun, `execution-model-and-durability.mdx:143,186`) and checks what reconcile relies on; the UI-server reconcile itself is tested in `agent-api.test.ts`. A real version change is left to the release check (tier B).
9.  **Open risk 4's mitigation is an `afterAnswer` callback in the host-port skeleton, not a timer.** The design requires the held report to go out only after the settle hook's call is answered; a `setTimeout` in the handler can fire before the response is written. Running the work after the body's last chunk is pulled ties it to the answer; the tier-A case records whether Eve would have waited anyway.
10. **The offered set switches to the record in the record commit.** The record has no Sensei result before this step's CI run (step 4's entries say `untested`), so switching earlier would offer no agent and break every commit after it. The switch and the record land together, and so do the test updates that assume today's list.
11. **From commit 12 Cursor is not offered for either persona.** The design's rule (D1, "Offered agents": from step 5, a row is offered when its latest record passes for both personas) has this consequence because Cursor has no record until its tier-B run; until commit 12, step 4's Cursor gate is extended from interactive to kata Sensei (and to `select` for learner workspaces), since both Sensei paths are on Eve from commit 9.
12. **Kata observations take their sources from Eve's evidence store and stay in `web.json` `learnerObservations`.** `recordLearnerObservation` requires a cited excerpt (`learner-observations.ts:14`), and Eve sessions' excerpts are in `.dojo/learner-evidence.json` (step 4); the observations' own store is unchanged because nothing else reads them and step 7 decides `web.json`'s future.
13. **The shipped record is a JSON import in protocol.** The design puts the registry and the record in protocol (step 3 decision 6) and the browser's evaluation settings read `offeredAgents()` (fact 17), so the record must load without `node:fs`. If `tsc` does not emit `dist/conformance.json` (commit 1's check), protocol's `build` script copies it after `tsc`.
14. **Commits 9 and 10 are pushed together.** The rewritten page cannot pass the ACP `test:lesson`, and the Eve `test:lesson` cannot pass before the page moves; each commit still type-checks and builds, which is the roadmap's rule for every commit.
15. **The composer hint while a question is open reads "Answer Sensei's question above, or type your answer".** The design lists the hint (traceability R6) without its text; a typed message answers the first open question (Eve docs `tools/human-in-the-loop.md:338,346`), which the hint says.
16. **CI limits: `verify` 60 minutes, `conformance` 80.** `test:lesson` on Eve adds a begin turn, check, held, dropped, guard, leave and completion flows on a cold OpenCode bootstrap (about 4-6 minutes, from step 4's interactive estimate). Tier A adds nine host cases per agent at about 20 s each and five scripted cases at about 5 s per process (about 3.5 minutes per agent, about 21 minutes in all) to step 4's estimate of 30-38 minutes.
17. **The global `@opencode/cli` install stays.** After this step nothing in the job may need it (both runtime scripts use a fixed catalog and the bootstrapped OpenCode), but whether any remaining script or spec in the job calls `opencode` from `PATH` is unverified here; step 7, which deletes ACP, removes it with its last user.
18. **The `replaced` socket message is sent only when the UI server replaces a session itself (a resume failure at a settle).** The begin's failure is still answered inside `POST /sessions/default` (step 4 decision 17), because every begin is sent from that request; the socket carries the one replacement the browser does not ask for.
19. **Guard notices raised without a socket are kept in the guard store and sent once when the page key's socket next opens.** The design asks for a persisted notice shown when the lesson next opens; using the socket that already carries live violations needs no new route.
20. **`navigate` refuses an incomplete lesson.** `POST …/progressions` already refuses one (`routes.ts:131-133`); the completion tool and the "Open next lesson" fallback share `advanceLesson`, so neither can skip a lesson whose checks have not passed.
21. **The offered set checks persona results, not CLI version ranges.** The design keeps a range per entry but does not say an installed CLI outside it is not offered; tier A pins the CLI the adapter bootstraps, and Grok runs the user's own binary (step 3 fact 2), so a range check would refuse Grok on most machines without tier B. The range stays informational until a step uses it.
22. **The Pi login is not settled further in this step.** Step 4 implemented the read-only credential store over the user's `auth.json` (step 4 decision 27); tier A uses fixture credentials, and whether a real Pi OAuth login works through it is unverified until a tier-B run with a Pi login.
