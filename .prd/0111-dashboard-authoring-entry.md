# 0111: Create an independent draft from the local dashboard

Parent: 0100/0107. Status: local implementation verified; broader FX prerequisite gate incomplete; unmerged review only.

Goal: the Pages New course card creates a separate kata draft with the existing Kyoshi scaffold, opens the correct owned authoring workspace and returns to its native conversation after reload/restart. Existing tutorials, installations, sessions and explicit external Eve hosts remain isolated.

Evidence: LearningLibrary already supports onNewCourse, but the native dashboard supplies no handler. scaffoldAuthoringWorkspace and observeWorkspacePath already exist. resolveWorkspaceId requires workspace configuration that the bare scaffold does not create. The control-plane authoring list currently requires a legacy kyoshi.json file. The default UI authoring mount pins one root and returns “This Eve host belongs to a different authoring workspace.” for a different workspace; removing this restriction would reuse the wrong native host. acquireKyoshiRuntime already owns one local runtime per canonical root. A root draft link without the accepted Eve session ID would start another native conversation; use a browser bookmark of the native ID, with the URL and Eve remaining authoritative.

Implementation boundaries: create only under the existing local Dojo state home's drafts directory; accept no client-supplied filesystem path and reject unsupported inputs before creating anything. Use the existing kata scaffold/configuration and workspace registry. Recognise newly managed drafts before their first conversation while preserving existing external draft discovery. Keep the fixed Eve mount unchanged and use it separately for each locally owned root; explicit EVE_BASE_URL/DOJO_EVE_ROOT retains its fixed ownership. Never retry a turn or create a session on infrastructure retry. Dashboard session links cache native IDs only, never conversation contents. Follow the Pages New course action directly with the default name New course, which can be renamed through the existing authoring control; do not add an unplanned name dialog. Failed creation must stay on the dashboard with an actionable error and retry.

Gate: red-first control-plane tests prove independent directories, real scaffold/configuration, listing/lookup after a new route instance, duplicate names without overwrite, no agent sessions, invalid names/paths/origins causing no new files, and unchanged installation/tutorial sentinels. Mount tests prove concurrent deduplication per root, separate roots, fixed-host rejection, body/query forwarding, retry isolation and close-all/idempotent shutdown. UI/UIX/authoring type checks and relevant complete non-live suites pass. The built CLI browser gate creates a draft in isolated state, verifies real files/listing and failed creation recovery, persists a native conversation link, restarts and reopens that same draft. Real Eve/native inference is scripted locally; no paid calls. Inspect the current Pages dashboard/authoring screenshots and verify no unexpected model/session or course-source writes. Preserve both user Storybooks, website routes and all 18 concurrent root audit files.

Baseline: control routes/workspace/fixed Eve mount suites passed 21 tests (414ms) on 2026-10-27 before implementation. Full goal/release acceptance remains in 0110; do not merge ahead of review.
