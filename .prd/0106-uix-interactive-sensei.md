## Implementation and local acceptance

The existing synchronous step/answer store remains version 1. Optional conversation bindings retain only native session/harness/model identifiers in that same file; transcript content remains owned by the native harness. Canonical workspace/course APIs and explicit resource targets allow two installed courses to retain independent progress without changing `.dojorc`. The legacy entry remains supported, including an explicit course query. Reading and answer submission do not start an agent or depend on conversation loading. A failed native resume is surfaced without substituting a new session.

Each turn carries the actual hydrated current step/material and saved answer. Interactive sessions use the existing ACP client and AG-UI stream bridge with no kata MCP profile. Successful explicit model choices are restored through the native setter; failures preserve the saved choice. The real UI uses the same controlled InteractiveLesson component as its present/question/complete stories, together with UIX workspace/composer and the extracted existing host rich-message renderer. Outdated conversation loads cannot overwrite a newly selected course's history.
