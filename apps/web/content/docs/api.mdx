---
title: Courses API
description: Browse courses and record privacy-preserving lifecycle progress.
---

The public API is served from `https://dojocho.ai/api/v1`. Its browsing routes follow the
[skills.sh API](https://www.skills.sh/docs/api) contract with `skills` renamed to `courses`.

## Browse courses

```http
GET /api/v1/courses?view=all-time&page=0&per_page=100
GET /api/v1/courses/search?q=effect&limit=50
GET /api/v1/courses/curated
GET /api/v1/courses/:source/:slug
```

The listing response uses `{ data, pagination }`. Search uses
`{ data, query, searchType, count, durationMs }`.

## Course metadata and progress

Dojo-specific data stays outside the compatible course object:

```http
GET /api/v1/course-profiles
GET /api/v1/courses/:source/:slug/metrics
```

Metrics include installs, started, progressing, finished, completion rate, and per-kata
started/finished/active counts.

## Record a lifecycle event

```http
POST /api/v1/events
Content-Type: application/json

{
  "instanceId": "opaque-project-id",
  "courseId": "dojocho/effect-ts",
  "event": "kata_completed",
  "kata": "001-hello-effect",
  "occurredAt": "2026-08-11T10:00:00.000Z"
}
```

`event` is one of `installed`, `started`, `kata_completed`, or `finished`. Repeating the same
course, instance, event, and kata is idempotent. The server stores a SHA-256 hash of
`instanceId`, not the submitted identifier.
