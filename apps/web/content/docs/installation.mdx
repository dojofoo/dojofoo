There's nothing to install globally: the CLI runs through `npx`.

Check that it runs:

```sh
npx dojofoo --help
```

## Requirements

- **Node.js 24** or newer.
- **A coding agent** for the sensei. The lesson UI runs it on OpenCode (the default), Codex,
  Cursor, Grok or FX – see [ui](/docs/commands/ui#the-senseis-agent).
- **mise**, which `npx dojofoo install` adds for you when it's missing. On Windows, install it
  first with `winget install jdx.mise`.

## Course environments

Courses pin their own languages and tools with [mise](https://mise.jdx.dev). When a course has
a `mise.toml` (or `.mise.toml`), dojofoo runs `mise install` and then the course's `setup` task,
if it defines one:

```toml
[tools]
node = "24"
pnpm = "10"

[tasks.setup]
run = "pnpm install"
```

mise may ask you to trust a course's configuration before it runs it. When dojofoo installs mise,
it places the binary at `~/.local/bin/mise` and leaves your shell startup files alone.

## What goes where

| Path | What it holds |
| --- | --- |
| `courses/<name>/` | An installed course |
| `katas/` | Your solutions |
| `.dojo/` | Project settings, progress and the anonymous project ID |
| `.agents/` | The dojofoo skill, and the deprecated `/kata` and `/dojo` commands, linked into each agent's folder |
| `~/.dojofoo/dojofoo.db` | The lesson UI's index of workspaces and sessions |

Everything in the project is a plain file you can commit. Set `DOJOFOO_HOME` to keep the
`~/.dojofoo` files somewhere else.

## Uninstall

Remove a course with [`npx dojofoo remove <name>`](/docs/commands/remove). To remove dojofoo
from a project, delete the paths above.
